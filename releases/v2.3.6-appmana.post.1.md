AppMana containerd 2.3.6-appmana.post.1

Upstream base: containerd v2.3.6, merged into the fork line. Everything outside
the changes listed below is upstream v2.3.6 unchanged.

## What the fork adds over upstream

- **CNI CHECK readiness in sandbox status and list.** For a sandbox that is
  otherwise ready, `PodSandboxStatus` and `ListPodSandbox` run CNI CHECK and
  report the sandbox NOTREADY when a plugin reports that its networking is stale
  or invalid, so the kubelet replaces it. Host-network sandboxes, sandboxes
  without a CNI result, and plugins or CNI config versions that do not support
  CHECK are left alone. `disable_check_pod_status = true` in the CRI CNI
  configuration turns this off.
- **CHECK result cache.** The CHECK result is kept per sandbox for 30 seconds
  and shared by concurrent callers, so the list and status calls agree and a
  plugin is invoked at most once per sandbox per 30 seconds rather than on every
  kubelet relist. A CHECK abandoned because its caller's context ended is not
  cached, and results are dropped when the sandbox is removed.
- **Recovery of stale sandbox-name reservations.** When `RunPodSandbox` finds
  the sandbox name reserved for a sandbox ID that is no longer in the sandbox
  store, it releases the stale reservation and proceeds. A failed
  `RunPodSandbox` always releases its name reservation, including when its
  cleanup was incomplete, so a retry for the same pod attempt is not rejected
  with "sandbox name is reserved".
- **Windows HCN namespace endpoint cleanup** (new in this release). Removing a
  sandbox network namespace on Windows now first lists the HCN endpoints still
  attached to the namespace. Each endpoint that still exists is detached from
  the namespace, confirmed detached, and then deleted, before the namespace is
  deleted; previously the namespace was deleted directly, which fails while an
  endpoint is attached. This covers a partial CNI ADD that left an endpoint
  behind and was followed by a failed CNI DEL. If the namespace still cannot be
  deleted because it references endpoints that no longer exist, the error names
  those endpoint IDs. Default HCN namespaces (host default, guest default) are
  never removed. When stopping a sandbox whose network setup never completed, a
  CNI teardown error no longer hides a failure to remove the namespace: both are
  returned.

## Artifacts

- `containerd-2.3.6-appmana.post.1-windows-amd64.tar.gz`: `containerd.exe`,
  `ctr.exe` and `containerd-shim-runhcs-v1.exe` (hcsshim v0.15.0-rc.4, the
  version upstream pins in `script/setup/runhcs-version`). `SHA256SUMS`,
  `provenance.txt` and `build-metadata.txt` describe this build. The archive is
  the one the workflow tested natively on Windows Server 2022 and Windows
  Server 2025.
- `containerd-2.3.6-appmana.post.1-linux-amd64.tar.gz` with its `.sha256sum`:
  `containerd`, `ctr`, `containerd-stress` and a static
  `containerd-shim-runc-v2`, built with the upstream release Dockerfile
  (`make release`).

Both are built with Go 1.26.8, the version upstream v2.3.6 requires.
